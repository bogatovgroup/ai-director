# Задание для администратора: выгрузка сайта ai-dir.ru на VDS (hsvds.ru)

Сайт статический (HTML, CSS, JS, картинки, видео) плюс один PHP-файл для приёма заявок. Базы данных нет.

## 1. Что нужно получить в итоге
- Сайт открывается по `https://ai-dir.ru`. Адреса `http://ai-dir.ru`, `http://www.ai-dir.ru` и `https://www.ai-dir.ru` перенаправляются (301) на `https://ai-dir.ru`.
- Форма заявки на главной отправляет данные на `/api/lead.php`. Заявка записывается в файл и уходит письмом на info@aiskolkovo.ru через SMTP.
- Сертификат Let's Encrypt с автопродлением, заголовки безопасности, сжатие, кэш (готовый конфиг: `tools/nginx-site.conf`).

## 2. Что стоит на сервере
- ОС: Ubuntu 22.04 или 24.04 (образ LEMP на hsvds.ru подходит). Ресурсы: 1 ядро, 1 ГБ RAM, 20 ГБ SSD достаточно.
- Пакеты: `nginx`, `php-fpm` (8.1 и выше) с расширениями `curl`, `mbstring`, `certbot`. MySQL не нужен.
- Файрвол: открыть только 22 (лучше ограничить по IP или ключу), 80, 443.
- fail2ban и автообновления безопасности (`unattended-upgrades`). Вход по SSH только по ключам, root-вход по паролю закрыт.

## 3. Домен и DNS (важно)
Домен `ai-dir.ru` зарегистрирован 24.10.2026 у REG.RU, оплачен до 24.10.2027. На 26.10.2026 по данным реестра:
- **Статус «UNVERIFIED»: нужно подтвердить данные владельца домена** (через REG.RU: письмо на почту владельца или Госуслуги). Если не подтвердить в срок (обычно 14 дней с регистрации), делегирование домена приостанавливается. Владельцу срочно проверить почту и личный кабинет REG.RU.
- Серверы имён сейчас **Cloudflare** (`lady.ns.cloudflare.com`, `otto.ns.cloudflare.com`). Возможны два варианта:
  1. Оставить DNS в Cloudflare, но записи `A` для `ai-dir.ru` и `www` сделать в режиме **«DNS only» (серое облако)**, без проксирования: иначе трафик посетителей (в том числе персональные данные из формы) идёт через иностранную инфраструктуру, а в документах заявлено хранение в РФ.
  2. Перенести DNS на REG.RU (или DNS hsvds), если там есть редактор зон.
- Записи: `A  ai-dir.ru → IP сервера`, `A (или CNAME)  www → тот же адрес`. Сейчас домен указывает на парковочную страницу REG.RU, её нужно заменить.
- IPv6: если не настроен, не создавать запись `AAAA`.

## 4. Порядок работ (подробно в `tools/DEPLOY-hsvds.md`)
1. Базовая защита сервера, установка пакетов.
2. Загрузка сайта в `/var/www/aidir` (содержимое папки `dist/`, готовится командой `python tools/build_dist.py ai-dir.ru` на компьютере владельца, либо владелец присылает готовую папку или архив). Владелец `www-data`, права: каталоги 755, файлы 644.
3. Конфиг nginx из `tools/nginx-site.conf` (домен уже подставлен). Версию PHP в строке `fastcgi_pass` указать по факту (`ls /run/php/`). Порядок: сначала блок на порту 80 → получить сертификат (`certbot certonly --webroot ...`) → включить блоки с `ssl`.
4. Файл настроек заявок **вне папки сайта**: `/var/www/lead_config.php` (образец в `tools/DEPLOY-hsvds.md`, шаг 6; права 640, владелец `www-data`). В него входят адрес почты, SMTP-данные и (опционально) вебхук Битрикс24. Этот файл не должен попадать в Git и в папку сайта.
5. Каталог для журнала заявок `/var/lib/aidir-leads` (права 750, владелец `www-data`).
6. Проверка (шаг 8 в `DEPLOY-hsvds.md`).

## 5. Что должен прислать владелец
- SMTP-данные почты info@aiskolkovo.ru: сервер, порт (465 SSL или 587 STARTTLS), логин, пароль приложения. Пароль передавать не в чат с исполнителем, а напрямую администратору защищённым способом.
- Если нужна передача заявок в Битрикс24: вебхук с правом **только** `crm.lead.add`.
- Подтверждение, что домен подтверждён в REG.RU (см. п. 3).

## 6. Приёмка (чек-лист)
1. `https://ai-dir.ru` открывается без предупреждений браузера, редиректы работают (http, www).
2. Тестовая заявка: письмо пришло, запись в `/var/lib/aidir-leads/leads.jsonl` появилась (`tail`).
3. Закрыты прямые обращения: `/lead_config.php`, `/.git/config`, `/tools/`, `/extras/` и GET на `/api/lead.php` (405) не отдают содержимое.
4. `/robots.txt`, `/sitemap.xml`, `/404.html` на месте; несуществующий адрес отдаёт страницу 404 со статусом 404.
5. Видео воспроизводится с перемоткой (поддержка Range-запросов в nginx включена по умолчанию), PDF в окне открывается.
6. Проверка на securityheaders.com и ssllabs.com без критичных замечаний. Заголовок `Content-Security-Policy-Report-Only` включён: ошибки в консоли браузера собрать и прислать разработчику, потом заменить на боевой `Content-Security-Policy`.
7. `sudo certbot renew --dry-run` проходит успешно.
8. Включены регулярные снимки или резервные копии сервера у провайдера и копия каталога `/var/www/aidir` с `/var/lib/aidir-leads`.
9. Ротация журналов (`logrotate`) для `/var/log/nginx/*.log` настроена.

## 7. Чего на сервере быть не должно
`tools/`, `extras/` (в папку `dist/` они не попадают), любые `.py`, `.md`, `.git`, пароли в открытом виде внутри каталога сайта.

## 8. Ответ администратора: веб-сервер Caddy
Администратор выбрал **Caddy** вместо nginx. Готовый файл: `tools/Caddyfile` (домен ai-dir.ru уже подставлен). Что учесть:
- Сертификаты Let's Encrypt Caddy выпускает и продлевает сам, certbot и раздел про сертификат в `DEPLOY-hsvds.md` (шаг 5) не нужны. Нужны открытые порты 80 и 443 и DNS без проксирования (серое облако в Cloudflare).
- **PHP: версия 8.1 или новее (рекомендуется 8.3), PHP-FPM** с расширениями `curl` и `mbstring`. Файл `/run/php/phpX.Y-fpm.sock` указать в строке `php_fastcgi` в Caddyfile.
- Папка сайта `/var/www/aidir`, файл настроек заявок `/var/www/lead_config.php`, каталог журнала `/var/lib/aidir-leads` (шаг 6 в `DEPLOY-hsvds.md` остаётся в силе).
- Файлы `.htaccess` и `tools/nginx-site.conf` при Caddy не используются.
- Если Caddy нужен только как прокси к другому серверу (nginx/Apache на локальном порту), заголовки безопасности и кэш из `Caddyfile` перенести в тот сервер или оставить в Caddy, а обработку статики и PHP заменить одной строкой `reverse_proxy 127.0.0.1:ПОРТ`.
- Проверить `caddy validate --config /etc/caddy/Caddyfile` и `sudo systemctl reload caddy`; журнал: `/var/log/caddy/aidir.access.log` (создать каталог и выдать права пользователю `caddy`).
